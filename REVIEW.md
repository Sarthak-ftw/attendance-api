# REVIEW.md

## Starter Defect Catalog

The starter `app/main.py` contained numerous correctness, concurrency, schema-compliance, and performance defects. Below is the complete catalog of defects found, how each is detected, and how it was resolved.

| # | Where (function / line) | What is wrong | How you'd notice it (test, input, or symptom) | How you fixed it |
|---|---|---|---|---|
| 1 | Line 22, `MongoClient(...)` | `MongoClient` was initialized without `tz_aware=True`. PyMongo returns naive UTC datetimes, which crash when compared or subtracted with timezone-aware datetimes. | `TypeError: can't subtract offset-naive and offset-aware datetimes` when calculating durations. | Initialized `MongoClient(..., tz_aware=True)` so all Mongo datetimes return with `timezone.utc`. |
| 2 | Global / Startup | Zero indexes defined on collections. All queries ran full collection scans (`COLLSCAN`), and uniqueness could not be enforced by MongoDB. | `GET /admin/explain` shows `COLLSCAN` everywhere; queries become unacceptably slow on 100k+ documents. | Implemented `create_indexes()` during `lifespan` startup, creating 4 indexes on `employees` and 4 on `attendance_logs` with safe exception handling. |
| 3 | Lines 73–74, `health()` | Always returned `{"status": "ok"}` with HTTP 200, never checking whether MongoDB was actually connected. | Stop MongoDB and hit `GET /health`: still returns 200 OK instead of failing. | Execute `client.admin.command("ping")`; on failure, raise `HTTPException(503, "MongoDB unavailable")`. |
| 4 | Line 35, `compute_late_minutes()` | Used `punch_in.replace(hour=h, minute=m)` on punch-in's naive date without converting to IST, and failed completely on overnight shifts (e.g. 22:00–06:00). | A punch-in at 23:00 IST for an overnight shift evaluated shift start on UTC date instead of IST date; wrong late minutes. | Implemented `resolve_shift()` which converts punch-in to IST wall-clock time and determines correct shift start/end datetimes. |
| 5 | Line 36, `compute_late_minutes()` | Floored to minutes *before* comparing `> 10` (`int(secs/60) > 10`). Also did not truncate microseconds. | Punch-in at 09:40:01 IST (10 min 1 sec) was floored to 10 min, evaluating `10 > 10` as False → wrongly gave 0 late minutes. | Truncate timestamps to whole seconds first, compare raw seconds `> 600` (10 min grace), and floor only after exceeding grace. |
| 6 | Line 41, `compute_work_hours()` | Used Python's built-in `round(secs / 3600, 2)` which performs banker's rounding (round half to even). | 16,182 seconds (4.495 hours) rounded down to 4.49 instead of half-up to 4.50. | Implemented `round_half_up()` using `Decimal.quantize(ROUND_HALF_UP)`. |
| 7 | Lines 46–47, `compute_overtime()` | Missing 30-minute threshold check, mixed naive and aware datetimes, and failed on overnight shifts where shift end is on the next day. | 15 minutes worked after shift end returned 15 instead of 0; `shift_end` on overnight shifts compared against the same calendar day. | Measured minutes from `shift_end_dt` produced by `resolve_shift()`; returned `minutes if minutes >= 30 else 0`. |
| 8 | Lines 53–60, `EmployeeIn` | Unvalidated plain strings. Accepted invalid employee codes ("abc"), bad emails, `shift_start == shift_end`, and invalid calendar dates ("2026-02-30"). | `POST /employees` with `joined_on="2026-02-30"` or `shift_start="09:30", shift_end="09:30"` returned 201 Created. | Added Pydantic `Field` regex constraints (`^EMP\d{4,6}$`, email regex, `HH:MM`), calendar date verification, and `@model_validator` ensuring shifts differ. |
| 9 | Lines 66–67, `PunchInIn` | Accepted any status string (`status: str = "PRESENT"`) and loose `punched_at: Optional[int]` (floats, booleans, negative integers, seconds-looking integers). | `POST /attendance/punch-in` with `status="ABSENT"` or `punched_at=1783312500` (seconds) accepted. | Constrained status to `Literal["PRESENT", "WFH", "ON_DUTY"]` and `punched_at` to `EpochMs` (`StrictInt` between $10^{11}$ and $4.1 \times 10^{12}$). |
| 10 | Lines 79–83, `create_employee()` | Check-then-insert race condition (`if find_one: raise 409 else insert_one`). | 20 concurrent requests with the same `emp_code` created duplicate records or crashed. | Direct `insert_one()` relying on the unique index `{"emp_code": 1}`, catching `DuplicateKeyError` and returning 409 Conflict. |
| 11 | Lines 82 & 85, `create_employee()` | Stored naive local time via `datetime.now()` and returned the raw BSON datetime object in the response. | `created_at` in response was an ISO string or BSON object rather than an epoch millisecond integer. | Stored `datetime.now(timezone.utc)` and formatted `created_at` as integer epoch milliseconds via `dt_to_epoch_ms()`. |
| 12 | Line 93, `list_employees()` | Pagination skipped page 1 entirely: `skip = page * page_size` (for page 1, skipped 20 items). | `GET /employees?page=1` and `page=2` showed page 2 and page 3 results; first 20 employees could not be retrieved. | Changed offset calculation to `skip = (page - 1) * page_size`. |
| 13 | Line 94, `list_employees()` | Total count used `count_documents({})`, ignoring the `department` filter. | `GET /employees?department=Engineering` returned `total=200` instead of the count of Engineering employees. | Passed the filter: `count_documents(filt)` when filtered, and `estimated_document_count()` when unfiltered. |
| 14 | Line 95, `list_employees()` | No sort order specified (unstable pagination) and no validation for `page >= 1` or `page_size <= 100` (`page=0` or `page=-1` gave negative skips or 500s). | `page=0` crashed or behaved unpredictably; items returned in arbitrary order across requests. | Added `.sort("emp_code", 1)` and FastAPI query validation: `page: int = Query(default=1, ge=1)` and `page_size: int = Query(default=20, ge=1, le=100)`. |
| 15 | Line 101, `punch_in_endpoint()` | When `emp_code` was unknown, `emp` was `None`, causing `emp["shift_start"]` to raise an uncaught `TypeError` / 500 Internal Server Error. | `POST /attendance/punch-in` with unknown `emp_code` returned 500 instead of 404. | Added explicit check: `if not emp: raise HTTPException(404, "Employee not found")`. |
| 16 | Line 102, `punch_in_endpoint()` | Used `datetime.fromtimestamp()` (local timezone), did not truncate microseconds, and default "now" was naive local time. | Sub-second timestamps were stored; punches near UTC midnight mapped to wrong days. | Converted epoch ms to UTC datetime with `microsecond=0`, and used `datetime.now(timezone.utc).replace(microsecond=0)`. |
| 17 | Lines 104–105, `punch_in_endpoint()` | Check-then-insert race condition on `(emp_code, date)`. | Concurrent punch-ins for the same employee on the same day both succeeded, creating duplicate records. | Created compound unique index `{"emp_code": 1, "date": 1}` and caught `DuplicateKeyError` to return 409 Conflict. |
| 18 | Line 119, `punch_in_endpoint()` | Leaked internal MongoDB `_id` and added `"id": str(res.inserted_id)`. Returned raw BSON datetimes. | Response contained `"id": "60c..."` and raw ISO strings, violating `openapi.yaml`. | Built `format_attendance_record()` which excludes `_id` and `"id"` and outputs epoch milliseconds. |
| 19 | Lines 144–147, `list_attendance()` | Loaded the entire collection into memory with `list(find(q))`, sorting and paginating in Python with no secondary tiebreaker. | Memory spike and multi-second delay on 100k attendance logs. | Moved sorting and pagination into MongoDB: `.sort([("date", -1), ("emp_code", 1)]).skip(skip).limit(limit)`. |
| 20 | Line 149, `list_attendance()` | Leaked `"id"`, returned raw datetimes, and lacked default values for legacy records missing `history` or `half_day`. | Legacy records returned `history: null` or omitted `half_day`, failing client schema validation. | Formatted each record through `format_attendance_record()` which supplies defaults (`history: []`, `half_day: False`). |
| 21 | Lines 137–142, `list_attendance()` | No query parameter validation: accepted invalid dates ("2026-02-30"), allowed `date_from > date_to`, accepted invalid status strings, and allowed `page=0`. | `date_from=2026-09-10&date_to=2026-09-01` returned 200 with empty list; invalid dates bypassed validation. | Added `parse_date()` for calendar validation, verified `date_from <= date_to`, validated status enum, and enforced pagination bounds. |
| 22 | Line 95, `list_employees()` | Returned `created_at` as a raw BSON datetime object because `{_id: 0}` projection only removed `_id`. | `GET /employees` returned `created_at: "2026-07-01T00:00:00"` instead of integer epoch milliseconds. | Formatted every employee with `format_employee()`, converting `created_at` to epoch milliseconds. |

## Non-Defects (Examined & Confirmed Correct)

The following items in the starter were reviewed and determined **not** to be defects:

1. **`load_dotenv()` behavior**:
   By default, `dotenv.load_dotenv()` does **not** override variables that already exist in the system environment (`override=False`). Real environment variables correctly take precedence over local `.env` files.
2. **IST Timezone Definition**:
   `IST = timezone(timedelta(hours=5, minutes=30))` correctly represents Indian Standard Time (UTC+05:30).
3. **MongoDB Collection Names**:
   The collection names `employees` and `attendance_logs` align exactly with `DATA_MODEL.md`.
4. **Initial Attendance Document State**:
   Initializing `punch_out: None`, `work_hours: None`, `overtime_minutes: 0`, `half_day: False`, and `history: []` upon punch-in accurately reflects the data model state before punch-out or regularization occurs.
